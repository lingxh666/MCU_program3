# UART7 485 采集改造计划（超标留样/流量触发）

## 目标
- 将“超标留样”和“流量触发”的数据来源从 ADC 改为 UART7 的 485 通讯。
- 继续沿用现有校准与判定逻辑，只替换数据源与触发条件。
- 仅在留样模式=超标留样或采样模式=流量触发时启用 UART7 读取。
- UART7 超时只记录警告，不影响采样/送样流程。

## 协议与采集
- 串口：UART7，9600，8N1，485 自动方向（不控制 DE/RE）。
- 轮询周期：5s。
- 固定发送帧：`01 03 00 08 00 06 44 0A`。
- 有效帧判定：
  - 帧头 `01 03 0C` 且总长度=17 字节即认为有效。
  - 不做 CRC 校验。
- 解析 6 个寄存器（每个 2 字节，大端）：
  - 顺序：COD、氨氮、总磷、总氮、PH、流量。
  - 原始值为 4-20mA 电流 * 1000。
  - 实际电流(mA) = 原始值 / 1000。
  - 原始值为 0 视为该通道未启用/无效。

## 数据映射与校准
- 通道映射：
  - channel 0 = COD
  - channel 1 = 氨氮
  - channel 2 = 总磷
  - channel 3 = 总氮
  - channel 4 = PH
  - channel 7 = 流量
  - channel 5 保留为空（未启用）
- 校准沿用现有逻辑：
  - 通道 0-4：使用 `channelCals[i].CalAD/CalValue` 做比例换算。
  - 流量：使用 `FlowADLower/FlowMeterBase` 公式
    `flow = (I-4) / (Ical-4) * FlowMeterBase`。
- `channelCurrent[]` 填入 UART7 解析得到的电流值（mA）。
- `channelData[]` 填入校准后的因子值/流量值。

## 1分钟有效判定
- 超标判定与流量变化必须“持续 1 分钟”才认为有效。
- 基于 5s 轮询：
  - 连续 12 次有效采样满足同一状态（超标/不超标、流量高/低）才确认状态切换。
  - 中途出现无效帧或通道原始值为 0，则清零计数并不触发判定。
- 超标触发：只有持续超标满 60s 才触发留样判定。
- 流量触发：只有流量高/低状态持续 60s 才触发开始/停止通知。

## 任务/模块调整
- 替换 UART7 的西安协议任务：
  - 移除/禁用 Xi’an 协议处理，复用 `task09` 作为 UART7 485 轮询任务。
  - 使用 `queue_moduleAI_handle` 接收 DMA+IDLE 帧。
- 数据处理入口：
  - 新增 UART7 数据处理函数，更新 `channelCurrent/channelData`，
    并调用现有超标/流量判定流程。
- ADC 处理：
  - 若“超标留样/流量触发”任一启用，则使用 UART7 数据路径。
  - 其它模式不启动 UART7 轮询，避免无谓通信。
  - ADC 逻辑保留，但在 UART7 生效时跳过 ADC 判定/触发路径。

## 超时与容错
- UART7 轮询超时：
  - 记录警告日志（限频，例如每 30s 一次）。
  - 标记“数据无效”，暂停超标/流量判定更新。
  - 不影响采样/送样状态机继续运行。
- 重新收到有效帧后恢复判定。

## 验证要点
- 使用示例帧验证解析与换算（如 `48 E3` -> 18.659mA）。
- 连续 12 帧超标/流量变化后触发事件，未满 1 分钟不触发。
- 模式不满足时 UART7 不轮询，不产生判定。
- UART7 超时仅告警，不阻塞采样/送样流程。
