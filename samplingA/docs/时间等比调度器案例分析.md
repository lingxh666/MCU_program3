# 时间等比调度器案例分析

## 概述

本文档详细分析时间等比调度器在不同配置下的启动模式、采样时序和送样时间点确定逻辑。

## 核心概念

### 1. 启动模式分类

| 模式 | 枚举值 | 条件 | 行为 |
|------|--------|------|------|
| 启动满量采样模式 | STARTUP_FULL_SAMPLING (0) | 时间充足，可完成n次等分采样 | 按计算的间隔进行多次采样 |
| 时间紧迫模式 | STARTUP_INSTANT_SAMPLING (3) | 时间不足以多次采样，但够一次大采样 | 立即进行一次周期总量采样 |
| 跳过到周期模式 | STARTUP_SKIP_TO_CYCLE (2) | 时间不够一次采样 | 放弃本次送样，等待下一个周期时间点 |

### 2. 核心算法

#### 周期整点确定
```c
if (final_delivery_min >= 30) {
    nearest_hour = (final_delivery_hour + 1) % 24;
} else {
    nearest_hour = final_delivery_hour;
}
```
- 送样时间分钟数 ≥ 30：周期整点为下一个小时的整点
- 送样时间分钟数 < 30：周期整点为当前小时的整点

#### 首次送样时间选择
- 
- 选择距离当前时间最近的**未过期**周期整点对应的送样时间点
- 跨天判断：如果当前时间已过所有当天的送样点，选择明天的第一个送样点

#### AB桶时序规则
- **A桶优先**：A桶永远是第一个采样和送样
- **必须先采样后送样**：任何送样前必须完成对应的采样
- **必须AB桶轮流采样和送样**：A桶在这一周期内采样，下个周期一定是B采样，送样同样是AB轮流






#### 构建采样送样周期时间表
- **送样时间表**： 根据判断A桶首次送样可以构建全天
- **采样时间表**：根据送样时间构建，必须先采样后送样，采样一定是在送样时间点对应周期时间的前一个周期时间
- **智能采样延迟**： 根据仪器分析时间和送样时间等因素智能推迟采样时间，代码已经只能够却实现

例1  送样时间点0:06 周期60分钟
周期整点确定  0:00 1:00  ....23:00
A桶送样时间点是2:06
A桶的采样周期在1：00-2：00   （在2:00之前的周期）
根据A桶的采样周期分配A桶采样时间点，全部采样落在1:00-2:00之间

例2  送样时间点0:58 周期120分钟
周期整点确定  1:00 3:00  ....23:00
A桶送样时间点是4:58
A桶的采样周期在3：00-5：00   （在5:00之前的周期）
根据A桶的采样周期分配A桶采样时间点，全部采样落在3:00-5:00之间





#### 首次采样间隔计算
```c
idle_time = available_time - total_sample_time
interval = idle_time / (sample_count - 1)
```
- **采样次数**：`cycle_time / SampleInterval`（固定值）
- **可用时间**：从当前到首次送样的时间
- **间隔时间**：动态计算，确保采样完成后正好到达送样时间

## 关键技术要点

### 1. 时间判断优先级
1. **送样时间点选择** > 周期整点确定 > 启动模式判断
2. **送样时间必须是最小间隔**：如00:05, 04:05, 08:05...
3. **跨天处理**：当所有当天送样点都过期时，选择明天的第一个送样点

### 2. 采样次数固定性
- 采样次数 = `cycle_time / SampleInterval`（整数除法）
- 不能动态调整采样次数，只能调整间隔时间
- A桶和B桶的采样次数可能不同

### 3. 首次采样的特殊性
- 首次采样间隔：动态计算，不是固定间隔
- 计算公式：`(可用时间 - 总采样时间) / (采样次数 - 1)`
- 目标：确保最后一次采样完成后正好到达送样时间点

### 4. 时间紧迫模式处理
- 当可用时间不足以完成多次采样时
- 立即进行一次大体积采样（周期总量）
- 不按时间表执行采样

## 60分钟周期的特殊性分析

### 1. 采样器资源管理

**核心原则**：采样器同一时间只能被一个桶使用，但采样和送样可以并行

- **时间充足模式**：A桶09:05送样，B桶09:05开始采样（采样器已空闲）
- **时间紧迫模式**：A桶09:05送样，B桶09:05开始采样（充分利用采样器）
- **等待整点模式**：A桶11:05送样，B桶11:05开始采样（无缝衔接）

**关键优势**：
- 采样器利用率最大化
- 采样和送样并行，提高系统吞吐量
- 只需管理分析仪器的排队等待

### 2. 分析时间的影响

**分析仪器独占性**：
- A桶送样后占用分析仪器58分钟
- B桶送样必须等待A桶分析完成
- 这导致B桶的实际送样时间推迟

### 3. 延时机制的差异

| 桶类型 | 首次采样 | 后续采样 | 延时原因 |
|--------|----------|----------|----------|
| A桶 | 0（立即） | 15分钟 | 预留送样和分析时间 |
| B桶 | 0（强制） | 15分钟 | 避免与A桶分析时间冲突 |

### 4. 设计改进建议

1. **错峰采样**：B桶采样时间应避开A桶采样时段
2. **采样器资源管理**：确保同一时间只有一个桶进行采样
3. **送样队列**：B桶送样应进入队列，等待分析仪器空闲

## 总结

时间等比调度器的核心思想是**时间优化**：
- 充分利用可用时间进行采样
- 确保采样操作在送样前完成
- 通过动态间隔计算实现精确的时间控制
- 根据时间约束自动选择最适合的启动模式

**60分钟周期的挑战**：
- 采样密度高，容易产生资源冲突
- 需要精细的并行操作控制
- 分析时间成为系统瓶颈
