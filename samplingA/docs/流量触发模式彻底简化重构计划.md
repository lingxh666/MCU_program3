# 流量触发模式彻底简化重构计划（逐文件+逐函数）

## 1. 目标与范围

### 1.1 目标行为（最终一致性定义）
- 流量上升沿触发后，固定执行：`瞬时送样 -> 满量采样 -> 等待整点 -> 周期采样/送样（复用时间等比逻辑）`。
- 流量下降沿触发后，固定执行：`立即停止采样/送样/留样 -> 排空A/B桶 -> 进入待机(IDLE)`。
- 待机后下一次流量上升沿必须重新完整触发，不允许出现“已在运行，忽略触发”。

### 1.2 本次重构范围
- 仅重构流量触发模式（`SamplingMode == 3`）链路。
- 时间等比、定时、开关、通讯模式逻辑不改业务语义。
- 允许修改接口与通知机制，但要求对外行为稳定可验证。

### 1.3 当前问题定位（供开发对照）
- `middlewares/bsp/Flowtrigger.c:341` `handle_flow_trigger_notifications()`：`is_running` 为真即忽略新触发。
- `middlewares/bsp/Flowtrigger.c:523`：停流处理放在 `cycle_started` 之后，等待整点阶段会提前返回，导致收尾不执行。
- `middlewares/bsp/Flowtrigger.c:896` + `middlewares/bsp/sampling.c:2442` + `middlewares/bsp/sampling.c:2664`：`0xFF` 停流通知被覆盖。
- `project/src/freertos_app.c:1461`：task4使用 `ulTaskNotifyTake` 单值语义，不适合多事件并存。

## 2. 目标状态机（替代现有分叉逻辑）

### 2.1 状态定义
- `FT_IDLE`：待机。
- `FT_START_INSTANT`：瞬时送样启动/运行。
- `FT_START_FULL_SAMPLE`：满量采样运行。
- `FT_WAIT_HOUR`：等待周期整点。
- `FT_CYCLE_RUNNING`：周期运行（复用时间等比采样/送样触发点）。
- `FT_FORCE_STOP_DRAIN`：停流强制停机与排空（短暂过渡态，完成后回 `FT_IDLE`）。

### 2.2 事件定义
- `EV_FLOW_START`：流量上升沿。
- `EV_FLOW_STOP`：流量下降沿。
- `EV_TICK_1S`：调度周期tick。

### 2.3 状态迁移
- `FT_IDLE + EV_FLOW_START -> FT_START_INSTANT`
- `FT_START_INSTANT 完成 -> FT_START_FULL_SAMPLE`
- `FT_START_FULL_SAMPLE 完成 -> FT_WAIT_HOUR`
- `FT_WAIT_HOUR 到整点 -> FT_CYCLE_RUNNING`
- 任意非 `FT_IDLE` 状态收到 `EV_FLOW_STOP`：`-> FT_FORCE_STOP_DRAIN -> FT_IDLE`

> 关键约束：`EV_FLOW_STOP` 优先级最高；任何阶段不允许“等待完成后再停”。

## 3.2 `middlewares/bsp/Flowtrigger.c`

### 改造目标
- 删除“停流后等待送样完成+留样回调停机”链路。
- 统一由状态机驱动，停流立即强制停机排空。

### 逐函数改造项

#### A. `ft_scheduler_init()`（`middlewares/bsp/Flowtrigger.c:189`）
- **动作**：只做状态机上下文初始化；默认 `FT_IDLE`。
- **禁止**：初始化后残留“运行中”或“等待完成”标志。

#### B. `ft_scheduler_start()`（`middlewares/bsp/Flowtrigger.c:203`）
- **动作**：语义改为“进入启动序列（仅内部/受控调用）”。
- **要求**：不再依赖 `flow_stopped` 来判断是否重置。

#### C. `ft_scheduler_stop()`（`middlewares/bsp/Flowtrigger.c:251`）
- **动作**：统一收敛到 `FT_IDLE`，清空事件与阶段态。
- **要求**：stop后必可重新触发上升沿启动。

#### D. `handle_flow_trigger_notifications()`（`middlewares/bsp/Flowtrigger.c:341`）
- **动作**：拆除“已在运行忽略触发”硬返回；改为事件入队/置位。
- **要求**：`EV_FLOW_STOP` 与 `EV_FLOW_START` 可同周期并存，处理时 `STOP` 优先。

#### E. `scheduler_flow_trigger()`（`middlewares/bsp/Flowtrigger.c:413`）
- **动作**：重写为单状态机调度入口。
- **处理顺序**：
  1. 读取并消费事件（原子）；
  2. 若有 `EV_FLOW_STOP` 且当前非 `FT_IDLE`，立即进入 `FT_FORCE_STOP_DRAIN`；
  3. 按状态推进（`START_INSTANT`/`START_FULL_SAMPLE`/`WAIT_HOUR`/`CYCLE_RUNNING`）；
  4. `FORCE_STOP_DRAIN` 完成后必回 `FT_IDLE`。

#### F. `calculate_cycle_start_hour()`（`middlewares/bsp/Flowtrigger.c:267`）
- **动作**：保留，作为“满量采样完成后的整点锚点计算”。
- **要求**：输出仅影响 `FT_WAIT_HOUR -> FT_CYCLE_RUNNING` 切换。

#### G. `ft_compute_sample_offsets()/ft_check_sample_trigger()/ft_handle_new_cycle()/ft_check_cycle_delivery_trigger()`（`middlewares/bsp/Flowtrigger.c:745/807/834/853`）
- **动作**：保留触发点计算能力，但仅在 `FT_CYCLE_RUNNING` 调用。
- **要求**：与时间等比模式触发点逻辑保持一致（复用优先）。

#### H. `flow_trigger_notify_start()`（`middlewares/bsp/Flowtrigger.c:930`）
- **动作**：仅置位 `EV_FLOW_START` 与时间戳；不直接改运行态。

#### I. `flow_trigger_notify_stop()`（`middlewares/bsp/Flowtrigger.c:944`）
- **动作**：仅置位 `EV_FLOW_STOP` 与时间戳；不再触发“等待留样完成”流程。

#### J. 旧回调函数处理
- `flow_trigger_handle_delivery_complete()`（`middlewares/bsp/Flowtrigger.c:896`）
  - **动作**：改为兼容空实现（仅日志），不参与停流收尾。
- `flow_trigger_retention_complete_callback()`（`middlewares/bsp/Flowtrigger.c:962`）
  - **动作**：降级为空实现/仅诊断日志。
- `notify_retention_task_flow_stopped()`（`middlewares/bsp/Flowtrigger.c:987`）
  - **动作**：移除调用路径（可保留空实现）。

### 新增内部函数（建议）
- `static void ft_enter_idle(void);`
- `static void ft_begin_start_sequence(uint32_t ts);`
- `static void ft_process_start_instant(void);`
- `static void ft_process_start_full_sample(void);`
- `static void ft_process_wait_hour(void);`
- `static void ft_process_cycle_running(void);`
- `static void ft_force_stop_all_and_drain(void);`

### 完成判据
- 代码中不再出现“停流后等待送样完成再停机”的路径。
- 任何阶段停流后，最多一个调度周期内进入排空并回待机。

## 5. 验收用例（必须全部通过）

## 5.1 功能用例
- 用例A：`IDLE -> FLOW_START` 后完整执行启动链（瞬时送样+满量采样）。
- 用例B：等待整点后进入周期，按时间等比触发采样/送样。
- 用例C：在 `START_INSTANT` 停流，立即中止并排空，回 `IDLE`。
- 用例D：在 `START_FULL_SAMPLE` 停流，立即中止并排空，回 `IDLE`。
- 用例E：在 `WAIT_HOUR` 停流，立即排空回 `IDLE`（重点覆盖旧bug）。
- 用例F：在 `CYCLE_RUNNING` 的采样中/送样中/留样窗口中停流，均立即停机排空。
- 用例G：停流后再次来流，必须重新触发启动链，不能打印“已在运行，忽略触发”。

## 5.2 稳定性用例
- 用例H：`start-stop-start` 快速交替（抖动），状态机不死锁。
- 用例I：连续多轮启动停止，A/B桶状态一致，不残留上下文。

## 6. 风险与控制

### 6.1 风险点
- 通知模型从“单值”改为“位语义”可能影响其它模式。
- 强制中止引入“半流程TSDB记录”增多，需要协议端容忍中止记录。

### 6.2 控制措施
- 先在流量模式开关下灰度：仅 `SamplingMode==3` 走新链路。
- 保留旧函数壳日志1个版本，便于定位残留调用。
- 对 task4 增加“模式与事件”日志，观察是否误入流量强停分支。

---

## 7. 交付标准
- 代码层：不再依赖 `flow_trigger_retention_complete_callback()` 进行停流收尾。
- 行为层：停流后 1 个调度周期内完成停机排空并回待机。
- 可观测层：再次流量触发必进入“步骤1：瞬时送样启动中”。
