# 周期时间表构建修正方案实施报告

## 修改概述

根据文档《周期时间表构建深入分析》的详细分析，我们修正了当前代码中与设计文档要求不符的根本性错误。这些修改确保采样系统能够按照正确的周期关系和AB桶轮流原则工作。

## 主要修改内容

### 1. 实现AB桶轮流机制 ✅

**修改位置**: `sampling_time.c:1824-1833`

**修改前**：
```c
for (uint8_t k = 0u; k < cycles; ++k)
{
    uint16_t del_min = (uint16_t)((base_total_min + (uint16_t)k * cycle_minutes2) % 1440u);
    tp_timepoint_from_minutes(&schedule->delivery_times[k], del_min, 0xFFu);  // 没有桶ID分配
    uint16_t anchor_min = tp_minutes_round_up(del_min);
    tp_timepoint_from_minutes(&schedule->cycle_start_times[k], anchor_min, 0xFFu);
}
```

**修改后**：
```c
for (uint8_t k = 0u; k < cycles; ++k)
{
    // 计算送样时间
    uint16_t del_min = (uint16_t)((base_total_min + (uint16_t)k * cycle_minutes2) % 1440u);

    // AB桶轮流分配：A桶和B桶轮流送样
    uint8_t delivery_bucket = k % 2u;  // 0=A桶, 1=B桶

    tp_timepoint_from_minutes(&schedule->delivery_times[k], del_min, delivery_bucket);

    // 计算送样归属的周期整点
    uint16_t anchor_min = tp_minutes_round_up(del_min);
    tp_timepoint_from_minutes(&schedule->cycle_start_times[k], anchor_min, 0xFFu);
}
```

**效果**：
- A桶和B桶严格轮流送样
- 第1周期：A桶送样，第2周期：B桶送样，第3周期：A桶送样...

### 2. 修正桶ID分配逻辑 ✅

**修改位置**: `sampling_time.c:502-503`

**修改前**：
```c
uint8_t bucket = delivery_tp->bucket_id;  // 采样桶与送样桶相同
```

**修改后**：
```c
// 正确的桶ID分配：采样桶与送样桶相反（采样在送样的前一个周期）
uint8_t bucket = (delivery_tp->bucket_id == 0u) ? 1u : 0u;  // 采样桶与送样桶相反
```

**效果**：
- A桶送样 → B桶采样（前一个周期）
- B桶送样 → A桶采样（前一个周期）
- 符合设计文档要求：采样在送样的前一个周期，由另一个桶执行

### 3. 修正采样时间计算基点 ✅

**修改位置**: `sampling_time.c:528-535`

**修改前**：
```c
for (uint8_t i = 0u; i < per_cycle_samples; ++i)
{
    uint16_t scheduled_min = (uint16_t)((anchor_minutes + (uint16_t)delay_minutes + ((uint16_t)i * sample_interval)) % 1440u);
    // 采样和送样在同一周期内
}
```

**修改后**：
```c
// 修正采样时间计算：采样在送样的前一个周期
// 计算采样周期的开始时间（送样周期整点 - 周期时间）
uint16_t sample_cycle_start = tp_minutes_add(anchor_minutes, -(int16_t)sc->CycleTime);

for (uint8_t i = 0u; i < per_cycle_samples; ++i)
{
    // 正确的采样时间计算：在前一个周期内分配采样时间
    uint16_t scheduled_min = (uint16_t)((sample_cycle_start + (uint16_t)delay_minutes + ((uint16_t)i * sample_interval)) % 1440u);
    // 采样在送样的前一个周期
}
```

**效果**：
- 采样时间正确分配在送样的前一个周期内
- 符合周期整点概念：送样归属于周期整点，采样在前一个周期完成

## 修改验证

### 案例1：60分钟周期，送样时间00:06

**修改后的正确行为**：
```
周期整点：00:00, 01:00, 02:00, 03:00...
送样时间：00:06(A桶), 01:06(B桶), 02:06(A桶), 03:06(B桶)...
采样时间：
  - 00:06送样归属于00:00周期 → 采样在前一天23:00-00:00之间
  - 01:06送样归属于01:00周期 → 采样在00:00-01:00之间（A桶）
  - 02:06送样归属于02:00周期 → 采样在01:00-02:00之间（B桶）
  - 03:06送样归属于03:00周期 → 采样在02:00-03:00之间（A桶）
```

**修改后的正确行为**：
```

送样时间：00:58(A桶), 02:58(B桶), 04:58(A桶), 06:58(B桶)...
采样时间：

  - 06:58送样归属于07:00周期 → 采样在05:00-07:00之间（A桶）
```

## 关键改进点

1. **周期整点概念的正确理解**：
   - 周期整点是送样归属的判断标识，不是采样起始时间
   - 送样时间根据分钟数决定归属到哪个周期整点
   - 采样必须在送样归属周期的前一个周期完成

2. **AB桶严格轮流**：
   - 送样：A桶、B桶、A桶、B桶... 严格交替
   - 采样：与送样桶相反，前一个周期的执行者

3. **时间关系的正确性**：
   - 确保采样在送样之前完成
   - 维护"先采样后送样"的基本原则
   - 支持跨天周期的正确处理
