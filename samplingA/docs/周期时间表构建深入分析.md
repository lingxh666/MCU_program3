# 周期时间表构建深入分析

## 一、核心概念理解

### 1. 周期整点概念及其关键作用

周期整点是时间表构建的**核心参考点**，它决定了送样时间属于哪个周期，以及采样应该在哪个周期进行。

```
周期整点确定规则：
- 送样时间分钟数 ≥ 30：周期整点为下一个小时的整点
- 送样时间分钟数 < 30：周期整点为当前小时的整点
```

**周期整点的作用**：
1. **周期边界标识**：每个周期整点标志着一个采样周期的开始
2. **送样归属判断**：送样时间归属于其对应的周期整点所代表的周期
3. **采样周期确定**：采样必须在送样对应周期的**前一个周期**内完成

**核心示例**：
- 送样时间 00:58 → 分钟数58 ≥ 30 → 周期整点：01:00
  - 00:58送样归属于01:00开始的周期
  - 采样必须在00:00-01:00之间完成（前一个周期）
- 送样时间 02:06 → 分钟数6 < 30 → 周期整点：02:00
  - 02:06送样归属于02:00开始的周期
  - 采样必须在01:00-02:00之间完成（前一个周期）

### 2. 时间表构建原则

基于周期整点概念，时间表构建遵循以下原则：

- **送样时间表**：根据A桶首次送样时间，按照周期时间间隔构建全天AB桶轮流送样表
- **采样时间表**：每个送样时间点对应的采样，必须安排在该送样所属周期的**前一个周期**
- **AB桶严格轮流**：A桶和B桶严格轮流进行采样和送样

**时间关系清晰图解**：
```
示例1：送样时间 00:58，周期60分钟
时间轴：  00:00────01:00────02:00────03:00
周期：    [周期0]   [周期1]   [周期2]   [周期3]
送样：             ↑00:58送样(归属于周期1)
采样：   [在00:00-01:00之间完成] (周期0)

示例2：送样时间 02:06，周期60分钟
时间轴：  01:00────02:00────03:00────04:00
周期：    [周期0]   [周期1]   [周期2]   [周期3]
送样：       ↑02:06送样(归属于周期1)
采样：   [在01:00-02:00之间完成] (周期0)
```

## 二、代码实现分析

### 1. 送样时间表构建（sampling_time.c:1822-1828）

```c
for (uint8_t k = 0u; k < cycles; ++k)
{
    // 计算送样时间：base_time + k * cycle_time
    uint16_t del_min = (uint16_t)((base_total_min + (uint16_t)k * cycle_minutes2) % 1440u);
    tp_timepoint_from_minutes(&schedule->delivery_times[k], del_min, 0xFFu);

    // 计算周期整点：向上舍入到最近的小时
    uint16_t anchor_min = tp_minutes_round_up(del_min);
    tp_timepoint_from_minutes(&schedule->cycle_start_times[k], anchor_min, 0xFFu);
}
```

**问题分析**：
- ✅ 正确计算了送样时间（base_time + k * cycle_time）
- ✅ 正确使用了 `tp_minutes_round_up` 计算周期整点
- ❌ 但没有按照文档要求设置桶ID（应该AB轮流）

### 2. 采样时间表构建（sampling_time.c:527-552）

```c
for (uint8_t i = 0u; i < per_cycle_samples; ++i)
{
    // 计算采样时间：anchor_minutes + delay + i * sample_interval
    uint16_t scheduled_min = (uint16_t)((anchor_minutes + (uint16_t)delay_minutes + ((uint16_t)i * sample_interval)) % 1440u);

    // 采样桶与送样桶相同
    uint8_t bucket = delivery_tp->bucket_id;

    tp_timepoint_from_minutes(&slot.sample_time, scheduled_min, bucket);
    slot.delivery_time = *delivery_tp;
}
```

**严重问题**：
1. **采样时间计算错误**：
   - 使用 `anchor_minutes + delay` 作为采样时间基点
   - 这使得采样和送样在**同一个周期**内
   - 正确做法应该是：`anchor_minutes - cycle_minutes + delay`（前一个周期）

2. **桶ID分配错误**：
   ```c
   uint8_t bucket = delivery_tp->bucket_id;  // 完全错误！
   ```
   - 根据文档，采样应该在送样的**前一个周期**
   - 如果送样是A桶，前一个周期的采样应该是**B桶**
   - 应该是：`uint8_t bucket = 1 - delivery_tp->bucket_id;`

### 3. 桶ID分配问题

代码中的桶分配逻辑（sampling_time.c:1821）：
```c
schedule->start_bucket = 0u;  // 固定A桶优先
```

**问题分析**：
- 固定A桶优先，导致所有送样都被分配给A桶
- 没有实现AB桶轮流机制
- 违反了文档中"AB桶严格轮流"的基本原则

**正确逻辑**：
- A桶送样 → B桶采样（前一个周期）
- B桶送样 → A桶采样（前一个周期）
- 严格交替，不能连续两次同一桶送样

## 三、文档与代码的主要差异

### 1. 采样与送样的周期关系（根本性错误）

| 文档要求 | 代码实现 |
|---------|---------|
| 采样在送样的**前一个周期** | 采样和送样在**同一个周期** |
| 周期整点：送样时间的归属标识 | 周期整点：采样时间的起始点 |
| 例：00:58送样→01:00整点→采样在00:00-01:00 | 例：00:58送样→采样也在00:58附近 |

**错误根源**：
- 代码完全误解了周期整点的作用
- 将周期整点当作采样起始时间，而不是送样归属判断

### 2. AB桶轮流原则

| 文档要求 | 代码实现 |
|---------|---------|
| A桶和B桶严格轮流送样 | 固定从A桶开始，全部A送样 |
| 采样桶与送样桶相反（前一个周期） | 采样桶与送样桶相同 |
| 例：A送样→B采样，B送样→A采样 | 例：A送样→A采样 |

### 3. B桶首次采样处理（设计缺陷）

代码中的特殊处理（sampling_time.c:513-523）：
```c
uint8_t is_first_b_cycle = (first_b_cycle_idx != 0xFFu) &&
                           (bucket == 1u) &&
                           (cycle == first_b_cycle_idx) &&
                           (!first_b_cycle_locked);

if (is_first_b_cycle) {
    // B桶首次采样在周期整点开始，不应该有延时
    delay_minutes = 0;
}
```

**问题**：
- 强制B桶首次采样在整点开始
- 没有考虑AB桶的时序关系
- 违反了"采样在前一个周期"的基本原则

## 四、正确的实现方案

### 1. 重新理解周期整点的作用

**核心认知转变**：
- 周期整点不是采样的起始时间，而是**送样归属的判断标识**
- 送样时间根据分钟数决定归属到哪个周期整点
- 采样必须在该送样归属周期的**前一个周期**完成

### 2. 修正采样时间计算（关键修正）

```c
// 错误的采样时间计算（当前代码）
uint16_t scheduled_min = anchor_minutes + delay_minutes + i * sample_interval;

// 正确的采样时间计算
uint16_t delivery_cycle_anchor = tp_minutes_round_up(delivery_minutes);
uint16_t sample_cycle_start = delivery_cycle_anchor - cycle_minutes2;  // 前一个周期
uint16_t scheduled_min = sample_cycle_start + delay_minutes + i * sample_interval;
```

### 3. 正确的桶ID分配逻辑

```c
// 送样桶分配（AB轮流）
uint8_t delivery_bucket = (cycle + start_bucket) % 2;
tp_timepoint_from_minutes(&schedule->delivery_times[cycle], delivery_min, delivery_bucket);

// 采样桶分配（与送样桶相反）
uint8_t sampling_bucket = 1 - delivery_bucket;  // 前一个周期的采样
```

### 4. 完整的正确实现方案

```c
void tp_plan_bucket_samples_correct(const SampleConfig *sc, DailyTimeSchedule *schedule, uint8_t start_bucket)
{
    uint8_t per_cycle_samples = sc->CycleTime / sc->SampleInterval;
    uint16_t cycle_minutes = sc->CycleTime;
    uint16_t sample_interval = sc->SampleInterval;

    for (uint8_t cycle = 0u; cycle < schedule->cycle_count; ++cycle)
    {
        // 1. 计算送样时间
        uint16_t delivery_min = (base_total_min + cycle * cycle_minutes) % 1440u;

        // 2. 确定送样桶（AB轮流）
        uint8_t delivery_bucket = (cycle + start_bucket) % 2;
        tp_timepoint_from_minutes(&schedule->delivery_times[cycle], delivery_min, delivery_bucket);

        // 3. 计算送样归属的周期整点
        uint16_t delivery_cycle_anchor = tp_minutes_round_up(delivery_min);

        // 4. 计算采样周期（前一个周期的开始）
        uint16_t sample_cycle_start = delivery_cycle_anchor - cycle_minutes;

        // 5. 确定采样桶（与送样桶相反）
        uint8_t sampling_bucket = 1 - delivery_bucket;

        // 6. 在采样周期内分配采样时间点
        for (uint8_t i = 0; i < per_cycle_samples; ++i)
        {
            uint16_t sample_min = (sample_cycle_start + i * sample_interval) % 1440u;

            // 创建采样槽
            TpOperationSlot slot = {0};
            tp_timepoint_from_minutes(&slot.sample_time, sample_min, sampling_bucket);
            slot.delivery_time = schedule->delivery_times[cycle];
            slot.is_valid = 1;

            // 保存到对应桶的数组
            if (sampling_bucket == 0) {
                schedule->bucket_a_slots[schedule->bucket_a_sample_count++] = slot;
            } else {
                schedule->bucket_b_slots[schedule->bucket_b_sample_count++] = slot;
            }
        }

        // 7. 记录周期整点
        tp_timepoint_from_minutes(&schedule->cycle_start_times[cycle], delivery_cycle_anchor, 0xFFu);
    }
}
```

## 六、总结

### 核心认知问题：对周期整点的根本性误解

当前代码的根本问题在于**完全误解了周期整点的作用**：

1. **周期整点的正确作用**：
   - 周期整点是**送样归属的判断标识**，不是采样起始时间
   - 送样时间根据分钟数决定归属于哪个周期整点
   - 采样必须在送样归属周期的**前一个周期**完成

2. **当前代码的严重错误**：
   - 将周期整点当作采样时间的起始基准
   - 导致采样和送样在同一个周期内
   - 违反了"先采样后送样"的基本原则

### 具体实现问题

1. **采样周期根本性错误**：
   - 错误：采样在送样的同一周期
   - 正确：采样在送样的前一个周期

2. **桶ID分配逻辑错误**：
   - 错误：采样桶与送样桶相同
   - 正确：采样桶与送样桶相反（前一个周期的执行者）

3. **时间计算基点错误**：
   - 错误：以周期整点为采样起始时间
   - 正确：以"周期整点-周期时间"为采样起始时间

4. **AB桶轮流机制缺失**：
   - 错误：固定A桶送样
   - 正确：AB桶严格轮流送样

### 修改的优先级和必要性

**必须立即修改（高优先级）**：
1. **修正采样时间计算基点**：使用`delivery_cycle_anchor - cycle_time`而不是`anchor_minutes`
2. **实现正确的桶分配**：采样桶使用`1 - delivery_bucket`
3. **实现AB桶轮流机制**：送样桶使用`(cycle + start_bucket) % 2`

**系统稳定需要（中优先级）**：
4. **添加智能延迟机制**：避免采样器和分析仪器的资源冲突
5. **完善边界情况处理**：特别是跨天和时间回退的处理

### 修改的紧迫性

这些修改不是优化，而是**功能性错误修正**：
- 当前代码实现的时间表与设计文档要求**完全相反**
- 会导致采样在错误的周期和错误的桶中执行
- 可能导致采样失败或数据不可用

**正确理解周期整点概念是实现可靠采样系统的基础**，必须立即修正这些根本性错误。
