## 一、重构目标

1. **变量地址重新规划** — 旧版地址分散且命名不规范，新版按功能模块统一编址
2. **消息分发解耦** — 旧版 `screen_message_dispatcher()` 过于庞大，拆分为独立处理模块
3. **双向同步机制** — MCU→屏幕 和 屏幕→MCU 的数据同步清晰分离
4. **发送可靠性** — 保留带重试的 `screen_send_notify()` 机制，增加发送队列
5. **适配新硬件** — 新增的传感器/执行器状态需要在屏幕上显示

## 二、通信协议格式

### 2.1 帧结构

```
[0x5A] [0xA5] [长度] [命令] [地址H] [地址L] [数据...]
```

| 字节位置 | 含义 | 说明 |
|----------|------|------|
| 0 | 帧头1 | 固定 0x5A |
| 1 | 帧头2 | 固定 0xA5 |
| 2 | 数据长度 | 从命令字节开始到末尾的字节数 |
| 3 | 命令 | 0x82=写变量, 0x83=读变量 |
| 4 | 地址高字节 | 变量地址高8位 |
| 5 | 地址低字节 | 变量地址低8位 |
| 6+ | 数据 | 变长数据域 |

### 2.2 命令类型

| 命令 | 方向 | 说明 |
|------|------|------|
| 0x82 | MCU→屏幕 / 屏幕→MCU | 写变量（设置参数或更新显示） |
| 0x83 | MCU→屏幕 | 读变量请求 |

### 2.3 页面切换命令

```
5A A5 07 82 00 84 5A 01 00 [page_id]
```

地址 0x0084 为系统页面切换寄存器。

## 五、消息分发架构重构

### 5.1 旧版问题

旧版 `screen_message_dispatcher()` 是一个巨大的 switch-case 函数，根据子命令字节（地址低字节）分发到不同处理逻辑，存在以下问题：

1. 单函数超过 1000 行，难以维护
2. 所有设置类型耦合在一起
3. 新增功能需要修改分发函数本身
4. 无法独立测试单个处理模块

### 5.2 新版架构

采用**地址段路由 + 模块处理函数**的两级分发机制：

```
screen_rx_handler()
  ├── 解析帧头 (5A A5)
  ├── 校验长度
  ├── 提取命令字节 + 地址
  └── screen_dispatch(cmd, addr, data, len)
        ├── addr 0x10xx → screen_handle_sampling_settings(addr, data, len)
        ├── addr 0x11xx → screen_handle_delivery_settings(addr, data, len)
        ├── addr 0x12xx → screen_handle_retention_settings(addr, data, len)
        ├── addr 0x13xx → screen_handle_comm_settings(addr, data, len)
        ├── addr 0x14xx → screen_handle_access_settings(addr, data, len)
        ├── addr 0x15xx → screen_handle_system_settings(addr, data, len)
        └── 未知地址 → 丢弃并记录日志
```

### 5.3 分发表设计

使用静态注册表替代 switch-case，便于扩展：

```c
typedef void (*screen_handler_t)(uint16_t addr, const uint8_t *data, uint16_t len);

typedef struct {
    uint16_t addr_base;     /* 地址段基址，如 0x1000 */
    uint16_t addr_mask;     /* 地址段掩码，如 0xFF00 */
    screen_handler_t handler;
    const char *name;       /* 调试用模块名 */
} screen_dispatch_entry_t;

static const screen_dispatch_entry_t dispatch_table[] = {
    { 0x1000, 0xFF00, screen_handle_sampling_settings,  "sampling"  },
    { 0x1100, 0xFF00, screen_handle_delivery_settings,  "delivery"  },
    { 0x1200, 0xFF00, screen_handle_retention_settings, "retention" },
    { 0x1300, 0xFF00, screen_handle_comm_settings,      "comm"      },
    { 0x1400, 0xFF00, screen_handle_access_settings,    "access"    },
    { 0x1500, 0xFF00, screen_handle_system_settings,    "system"    },
};
```

### 5.4 MCU→屏幕 同步机制

MCU 主动向屏幕推送实时状态，通过发送队列实现异步非阻塞：

```
screen_update_task() (周期性运行，如200ms)
  ├── 检查脏标记（哪些状态发生了变化）
  ├── 组装变更数据帧
  ├── 放入发送队列 (Queue09)
  └── 发送线程从队列取帧并通过 UART4 发送
```

**脏标记机制：**

```c
typedef struct {
    uint32_t actuator_dirty;    /* 执行器状态变更位图 */
    uint32_t system_dirty;      /* 系统状态变更位图 */
    uint32_t bucket_a_dirty;    /* A桶状态变更位图 */
    uint32_t bucket_b_dirty;    /* B桶状态变更位图 */
    uint32_t sensor_dirty;      /* 传感器状态变更位图 */
} screen_dirty_flags_t;
```

- 业务逻辑修改状态时置位对应脏标记
- 同步任务检查脏标记，仅发送变更部分
- 发送完成后清除脏标记
- 时间信息固定每秒更新一次，不使用脏标记

### 5.5 发送队列与重试

```c
typedef struct {
    uint8_t  buf[64];       /* 帧数据 */
    uint16_t len;           /* 帧长度 */
    uint8_t  retry_count;   /* 已重试次数 */
    uint8_t  max_retry;     /* 最大重试次数 */
    uint8_t  need_ack;      /* 是否需要确认 */
} screen_tx_msg_t;
```

- 发送队列深度：16 条消息
- 普通状态更新：`need_ack = 0`，发送即忘
- 关键设置回写：`need_ack = 1`，等待屏幕应答，超时重发（最多3次）
- 发送间隔：相邻帧间最少 5ms 间隔，避免屏幕处理不过来

### 6.3 页面切换逻辑

MCU 需要跟踪当前屏幕页面，仅刷新当前页面所需的变量，减少通信负载：

```c
static uint8_t current_page = 0;

void screen_on_page_changed(uint8_t page_id)
{
    current_page = page_id;
    /* 立即刷新新页面的全部变量 */
    screen_refresh_page(page_id);
}
```

**页面切换来源：**
- 屏幕触摸切换：屏幕主动通知 MCU 当前页面（通过写入约定地址）
- MCU 主动切换：报警/异常时 MCU 强制切换到对应页面
- 开机初始化：MCU 发送页面切换命令到主页面

### 7.3 实现步骤

#### 步骤1：底层帧收发

实现 `bsp_screen.c` 中的基础通信功能：

- UART4 DMA 接收 + 空闲中断检测帧边界
- 帧头校验（0x5A 0xA5）+ 长度校验
- `screen_write_var()` 组装写变量帧并发送
- `screen_read_var()` 组装读变量请求帧
- `screen_switch_page()` 页面切换命令
- 发送队列（FreeRTOS Queue）+ 发送任务

#### 步骤2：分发框架

实现消息分发机制：

- `screen_rx_handler()` 解析接收帧
- `screen_dispatch()` 根据地址段路由到对应处理函数
- 分发表注册（静态数组）
- 未知地址的日志记录

#### 步骤3：设置处理模块

逐个实现各 `screen_handler_xxx.c` 文件：

- 每个模块独立处理对应地址段的写入命令
- 解析数据并写入 KVDB（通过互斥量保护）
- 参数合法性校验（范围检查）
- 设置成功后回写确认值到屏幕

#### 步骤4：状态同步模块

实现 `screen_sync.c`：

- 脏标记管理（置位/检查/清除）
- 各模块同步函数（actuators/system/bucket_a/bucket_b/sensors）
- 页面感知刷新（仅同步当前页面所需变量）
- 时间同步（每秒固定更新）
- 开机时全量同步一次

#### 步骤5：集成与测试

- 将屏幕任务（Task02）与发送队列（Queue09）对接
- 屏幕初始化流程：上电延时 → 切换到主页面 → 全量同步设置参数 → 启动周期刷新
- 逐页面验证显示正确性
- 压力测试：快速切换页面、连续修改设置、长时间运行稳定性

### 7.4 迪文屏工程同步修改

屏幕端（DGUS 工程）需要同步修改以匹配新地址：

1. **变量地址全部更新** — 所有控件绑定的 VP 地址从旧版 0x50xx/0x52xx 改为新版 0x1xxx/0x2xxx
2. **页面编号对齐** — 按 6.1 节规划重新编排页面 ID
3. **新增页面** — 传感器页(4)、手动控制页(14)、关于页(15) 为新增
4. **时间显示改造** — 旧版 BCD 编码改为独立 uint16 字段，屏幕端数据变量类型对应调整
5. **日志页面** — 新增翻页控件，绑定 0x26xx 地址段
